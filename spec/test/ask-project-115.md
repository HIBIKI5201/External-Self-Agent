# #115 分類が分からない追加の確認
2026-10-12。合成のタスク・プロジェクト、隔離DB、偽Google API。本番チャットへ検証文を送らない。

## 検査
- `tests/test_ask_project.py`（オフライン 3 件、モデルの代役）: 似たタスクが Warframe にまとまっているとき、登録前に「Warframe」を先頭の候補にして聞き、追加は 0 件。「Warframeで」で 1 件だけ Warframe に追加し、再送で増えない。ボタンの「未分類で追加」、「やめて」、プロジェクトを言った依頼・「未分類でいい」と言った依頼は従来どおり。雑談モードでは似たタスクがないとき聞かずに未分類で追加する。
- 実モデルの検査 2 件（`test_literal_task_corrections`・`test_memory`）は、最初の追加で分類を聞かれるようになったので「未分類でいい」と答えてから元の確認をするように直した。
- 評価（qwen3:8b、k=3）: `ask-project-dev`（似たタスクあり→「Warframeで」）、`ask-project-holdout`（似たタスクなし→「未分類でいいよ」）を追加。名前を直す既存の 3 シナリオ（`correction-rename-*`、`literal-name-correction-new-holdout`）は、分類の確認中に名前を直し、その後「未分類でいい」と答える形にした。5 シナリオとも pass^3 = 1.0、不要な確認・正当な依頼の拒否 0。

## 修正中に見つけて直したこと
- 「週課のネットセルを追加して」は #135 の周期の確認に入り「名前を「」で囲んで」と返していた。名前を読めないときは通常の追加に任せる。
- 「〇〇を追加して」（「タスクに」なし）で、モデルが名前を「〇〇を追加」にしていた。入力どおりの名前を使う規則（#105）を「〇〇を追加して／登録して」にも広げた。先頭の「就活に」のようなプロジェクト名は名前に含めない。
- 分類の確認中に「名前を〇〇に直して」と言われたら、保留中のタスクの名前を直して聞き直す。

限界: 追加のたびに分類を聞くので、確認が 1 往復増える。プロジェクトを言うか「未分類でいい」と言えば従来どおりすぐ追加する。
