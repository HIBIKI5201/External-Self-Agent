# #53 会話からの実際の繰り返し設定

- 隔離DB・偽Google APIを使用。実アカウント・本番会話・保存済みのタスクは操作しない。
- 同じ周期での新規追加、対象と参照元を指定した既存設定、毎週／毎日の直接指定、直後の「それ」への後続依頼をモデルなしで検証。
- 参照元の周期と次回締切が新しいタスクに反映され、返事も保存された値から作られる。既存タスクのメモ・タイトル・プロジェクト・完了状態は維持する。同じ周期で追加する場合のプロジェクトは参照元を引き継ぐ。
- 対象不明・複数・参照元不在・参照元の周期なし・不正な時刻・未対応の月次周期では変更しない。別の会話を挟んだ「それ」は以前の操作対象へ勝手に結び付けない。単なる締切変更を周期設定として扱わない。
- 過去の追加がメモだけになった場合も、直近の実操作記録の対象が一意であり、元の依頼の参照周期が特定できるなら後続依頼で実際の設定にできる。既存の本番データを推測で一括修復しない。
- 設定後のタスクを完了し、時計を次のリセット点に進めて、正しい次回締切で未完了へ戻ることと重複リセットしないことを検証。解除は締切を維持する。
- 自由な表現すべての解析は保証しない。特定できない場合は番号・正確な名前・「毎週月曜9時」の形式を案内する。Googleネイティブの繰り返し機能にはならず、従来どおりE.S. Agentでのリセット結果が同期される。
- モデル不要57件成功・14件スキップ、全71件成功・スキップなし。Python構文と差分の空白チェックも実施。
- 稼働環境の更新・再起動・ヘルスチェックはマージ後にPRへ記録する。本番でのチャット送信や周期変更による検証は行わない。
