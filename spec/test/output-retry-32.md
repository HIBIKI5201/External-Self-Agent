# #32 モデル出力の検証と理由付き再生成

- 隔離DB・偽Google APIで検証。本番の会話・タスク・外部サービスへの書き込みは行わない。
- タスク判定: 有効な完了操作と存在しない番号を含む混合出力を拒否し、再生成前にどちらも実行しない。番号・日付・型・発言にないタイトル・変更の根拠を検証する。
- 偽モデルでは理由が渡ること、初回＋再試行2回で止まること、成功後の操作が1回だけであることを確認。
- 最初の20分: 元の内容にない会社・ツール候補、5行、未完の「以下の」を拒否。合格した全文だけ表示し、3回とも不合格なら一般的な一歩を返す。名称の検出は会社名の語形・英字・カタカナの候補と元の内容を照合する方式であり、すべての固有名詞を識別する保証はない。
- 手順スキル: 不在タスク・引数型・過去の締切を理由付きの不実行結果として返す。同一の成功済み呼び出しは再実行せず、失敗が3回続く場合は停止し、完了した操作があれば記録を案内する。
- ログ: 要求ごとに `validation.stage`、`validation.attempt`（0〜2）と `elapsed_ms` を記録し、コンテキスト終了後は通常の要求へ情報が漏れない。
- 実モデル `qwen3:8b` の隔離会話でも、初回に不在番号を返す状況から完了操作へ回復し、「反映できませんでした」にならないことを確認。当初は否定理由だけでは誤番号を再使用したため、再試行に元の依頼と現在の番号一覧を渡した。これは1つの合成事例であり、実会話全体の失敗率改善を測定したものではない。
- 結果: モデル不要52件成功・14件スキップ。全66件成功・スキップなし。変更したPythonの構文チェックと差分の空白チェックも実施。
- 稼働環境への反映・ヘルスチェックはマージ後にPRへ記録する。本番の強制失敗やチャット送信による検証は行わない。
