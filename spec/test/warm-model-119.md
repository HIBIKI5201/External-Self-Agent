# #119 最初の返事の読み込み待ち
2026-10-12 4 時台、この PC（RTX 4060 Laptop 8GB、qwen3:8b Q4_K_M、num_ctx 8192）。本番 DB のコピー（Sandbox）、雑談モード、同じ入力「今日はちょっと寒いね」。各試行の前にモデルをメモリから外した（`keep_alive: 0`）。読み上げ（VOICEVOX）は起動していない状態。

| 試行 | 先に読み込まない（従来） | 先に読み込む（読み込み約 3.0 秒、その後 2 秒待って送信） |
|---|---|---|
| 1 | 10,483 ms | 2,639 ms |
| 2 | 6,149 ms | 2,839 ms |
| 3 | 6,348 ms | 3,301 ms |

- モデルが載っている状態の返事（2 発言目、決まった応答の経路）は 90 ms 前後。
- 1 回目の従来値（10.5 秒）は、モデルのファイルが OS のキャッシュから外れていたためと考えられる（その後の 2・3 回目は 6 秒台）。Issue の 17〜23 秒は、さらにキャッシュが冷えた・VOICEVOX と同時に動いていた状態の値で、今回は再現していない。
- VRAM: モデルなし 1,536 MiB（他のアプリ）→ 読み込み後 7,571 MiB（8,188 MiB 中）。VOICEVOX を GPU で同時に動かすと余裕がほとんどない。VOICEVOX と同時の値は今回測っていない。
- 最初の実装は読み込みの依頼に `num_ctx` を付けておらず、Ollama が既定の大きさで読み込み、返事のときに読み込み直していた（先に読み込んでも 6.5 秒前後で速くならなかった）。返事と同じ `num_ctx` を付けて解消した。

## 検査
- `tests/test_warm_model.py`: 偽の Ollama で、外れているときだけ `/api/generate`（空のプロンプト、`keep_alive`、`num_ctx`）を 1 回送り、20 秒以内の重複・載っているときは何も送らない。状態（`loaded`）を返す。
- `tests/test_listen.js`: 会話モードの既存検査（話し始めに読み込みを頼む呼び出しは、読み上げの停止とは別に数える）。

限界: 先に読み込む効果は、送るまでに読み込みが終わる時間（打ち始めから約 3 秒）がある場合。すぐ送った場合は読み込みの途中から待つ。`keep_alive` 自体は変えていない（使っている時間帯だけ長くする案は未実施）。
