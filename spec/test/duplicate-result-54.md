# #54 重複防止と未反映の条件の区別

- 隔離DB・偽モデルを使い、本番の会話・Google・既存タスクは変更しない。
- 同じ追加依頼でタスクが増えず、変更番号・内容も変わらない。「登録済み」「新しく追加していない」と返し、反映失敗や不要な言い換え要求を出さない。通常の重複防止にはモデルの再試行を行わない。
- 重複に新しい締切・プロジェクト・メモ・繰り返し条件がある場合は、登録済みと未反映の条件を分けて返す。既存タスクを自動で変更せず、要求全体が満たされたと断言しない。既存メモに含まれる内容は不足としない。
- 実行処理に新規追加・重複・拒否が混在する場合も、実際の追加、登録済みで変更なし、未反映の操作を分ける。純粋な実行拒否は従来の失敗案内を維持する。
- #32の判定経路は不合格の混合操作を事前に拒否する。部分結果のテストでは実行処理を直接呼び、既存の呼び出し経路でも説明が正しいことを確認する。
