# 会話の評価（#96）

Es の会話の質を、モデル・プロンプト・コードの版ごとに比べるための仕組み。
**何が起きたか**（タスクの最終状態、変えてはいけないもの、二重の変更）で採点し、返事の言い回しは正規表現で採点しない。自然さは人が採点する。

## 2 つの使い方

| | 何を確かめるか | モデル | いつ |
|---|---|---|---|
| `tests/test_eval_invariants.py` | 無許可の変更・二重の変更・やっていない完了の名乗りが**決して起きない**こと | 使わない（わざと間違える代役） | CI で毎回（必須） |
| `tests/eval/run_eval.py` | 実際のモデルでの成功率・確認の多さ・遅さ | Ollama の実モデル | モデルやプロンプトを変えたとき、手元で |

### CI の不変条件テスト
シナリオごとに、モデルの代わりに「間違った書き込みを 1 つだけ提案し続け、返事では『完了にしました』と言い張る」代役を使う。
提案するのは、各タスクの完了・名前の変更・締切の変更・メモの追記と、タスクの追加。1 回に 1 つだけ提案する（まとめて出すと検証で全部まとめて落ち、どれか 1 つを通してしまう穴が隠れるため）。
シナリオの `forbid` に書いた変更が 1 つでも起きたら失敗する。

保護を外すと必ず落ちることを確かめてある（2026-10-10）: 「実行しないで」などの保留を外すと 2 件、完了の合図の確認を外すと 4 件、スキルの許可を外すと 21 件（161 回中）が失敗する。

### 実モデルの評価
```
python tests/eval/run_eval.py                    # 全シナリオ × 3 回
python tests/eval/run_eval.py --k 5 --split holdout
python tests/eval/run_eval.py --only 否定 部分失敗  # タグか ID の一部
python tests/eval/run_eval.py --model qwen3:14b   # モデルを替えて比べる
python tests/eval/run_eval.py --compare data/eval/<A>/result.json data/eval/<B>/result.json
```
結果は `data/eval/<日時>/`（コミットしない）に出る。
- `result.json` — すべての試行（発言・返事・記録・確認の結果・各モデル要求のトークン数と時間）と集計。
- `summary.md` — 指標の表とシナリオごとの結果。
- `review.csv` — 人が採点するシート（自然さ 1〜5、利用者の意図に合っているか、メモ）。Excel で開ける。

Ollama でモデルが使えないときは何も実行せず、`status: not_run` を書いて終わる（終了コード 2）。**実施していない評価を成功として扱わない。**

## 指標

| 指標 | 意味 |
|---|---|
| success_rate | 全試行のうち、そのシナリオのすべての確認が通った割合 |
| pass^k | k 回すべて通ったシナリオの割合。**毎回ちゃんと動くか**。 |
| pass@k | k 回のうち 1 回でも通ったシナリオの割合。**できることはあるか**。pass^k と混同しない。 |
| false_refusal_rate | 変更を頼んだシナリオで、何も変わらなかった割合（正当な依頼の拒否） |
| unneeded_confirm_rate | 変更を頼んだシナリオで、確認がいらないのに聞き返した割合 |
| false_claim_rate | 何も変えていないのに「追加しました」などと言った割合 |
| double_operation_rate | 同じメモの行や同じタスクが二重にできた割合 |
| turn_ms_p50 / p95 | 1 発言の処理時間（返事待ちの後の返事を含む） |
| requests / retries / tokens per turn | 1 発言あたりのモデル要求数・検証でのやり直し・入力と出力のトークン数 |
| dev_pass^k / holdout_pass^k | 分割ごとの pass^k |

結果には、コードの版（未コミットの変更の有無も）、モデル名と digest、設定、プロンプトの版（主なプロンプトのハッシュ）、シナリオの版を記録する。比べるときは、これがそろっているかを先に見る。

## シナリオ（`tests/eval/scenarios.json`）
過去の失敗（#67・#72・#73・#74・#80・#87・#88・#94・#95 など）をもとにした**合成の**会話。実際の会話の文や個人の情報は入れない。
- `split`: `dev` は修正に使った例に近いもの、`holdout` は修正に使っていない言い換え。holdout の成績が dev より大きく低いなら、特定の文だけに合わせた修正になっている。
- `via`: `chat`（入力欄）・`skill`（`/名前`）・`choice`（選択肢のボタン）・`voice`（音声認識の後の文。句読点がない）。どれも同じ確認で採点する。
- `turn.fault: after_change`: タスクが変わった直後のモデル要求で接続を切る。その後、サーバーの返事待ちの処理と同じことをして、二重の変更が起きないかを見る（#95）。
- `turn.confirm: true`: その発言では何も変えず、聞き返すのが正しい。
- `expect`: `tasks`（項目の値、`notes_once` は 1 回だけ、`notes_lacks` は含まない）、`unchanged`、`no_change`、`added`、`min_added`、`no_duplicate_titles`、`mode`、`not_pending`。
- `forbid`: CI の代役で決して起きてはいけない変更。`any`（何も変えない）、`add`（追加しない）、`only:A`（A 以外を変えない）、`complete:A`・`title:A`・`due:A`・`notes:A`。

新しい失敗が見つかったら、合成の会話にしてシナリオに足す。修正に使った言い方は `dev`、確認用の言い換えは `holdout` にする。
