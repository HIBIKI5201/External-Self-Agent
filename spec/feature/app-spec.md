# E.S. Agent 仕様ベースライン

2026-10-07 時点で、ユーザーとの対話で決めた内容と、実装済みのコードを突き合わせて整理した現行規則である。
E.S. Agent（正式名称 External Self Agent、2026-10-07 に EsAgent から改称）は、ローカル LLM（Ollama）で動く**常駐型のタスク管理アシスタント兼作業コンパニオン**で、
目指す体験は「Chill with You: Lo-Fi Story」のように**隣で一緒に作業してくれる存在**である。
コンパニオンの名前 Es は、フロイト心理学の「エス（イド）＝内なる衝動」に由来する。

読み方:

- **決定** — ユーザーとの対話で決めた規則。仕様の正本。
- **意図** — その規則を置いた理由。変更するときに守るべき狙い。
- **実装** — コードで確認できる事実（ファイル名つき）。
- **制約** — 外部サービスの規約や OS の制限など、こちらで変えられない条件。
- **未解決** — 決まっていない、または確認できていない事項。推測で補っていない。

対象外: Google Cloud の設定手順、Ollama のインストール手順などの導入作業は本書に含めない。
モジュール構成は `spec/domains/*.domain.json` を正とする。

## AS-01 全体構成と常駐

- **実装（#61）:** リリース版は `VERSION` が正本。0.2.0（2026-10-08）の変更一覧は `CHANGELOG.md`、検証と残る確認事項は `spec/test/release-0.2.0.md`。版の確定後にmainのリリースコミットへ `v0.2.0` タグを付ける。

- **決定:** E.S. Agent はこの PC に常駐する。本体は `C:\ESAgent`（階層を浅くするため C ドライブ直下）。ログオン時に自動で起動し、チャット画面はスタートアップアプリのように呼び出せる。
- **実装:** Python 標準ライブラリだけで動くローカル HTTP サーバー（`esagent/server.py`、`127.0.0.1:8765`）。Windows のタスクスケジューラのタスク `ESAgent` がログオン時に `pythonw server.py` を起動する（`install.ps1`）。
- **実装:** チャット画面は Edge のアプリウィンドウ（`--app=http://127.0.0.1:8765/`）。**Ctrl+Alt+E** またはスタートメニューの「E.S. Agent」で開く（`esagent/launch.py`）。**既に開いていれば前面に出し、無ければ開く**（`esagent/winfocus.py`）。
- **実装:** サーバー起動時にデスクトップの黒猫（AS-12）も起動する。黒猫はタスクスケジューラのジョブから外して起動する（`CREATE_BREAKAWAY_FROM_JOB`）。
- **意図:** 黒猫がタスクのジョブに残ると、サーバーが落ちてもタスクが「実行中」のままになり、再起動できなくなるため。
- **実装:** データは `data/`（SQLite `esagent.db`、ログ `esagent.log`、引き継ぎ文 `handoffs/`、黒猫の位置 `pet.json`）、秘密情報は `secrets/`、設定は `config.json`（いずれも Git の管理外。共有用の雛形は `config.example.json`）。
- **実装:** バックグラウンド処理 — Google 同期（3分ごと＋変更時）、繰り返しタスクのリセット判定（60秒ごと）、集中タイマー（1秒ごと）、返事待ちメッセージの処理（5秒ごと）。

## AS-02 モデルと判断の流れ

- **決定:** モデルは **Qwen3 8B**（`qwen3:8b`）、思考モードはオフ。旧モデル Phi-4-mini は削除した。
- **意図:** Phi-4-mini（3.8B）は「それぞれに締切を」のような複数タスクの更新や、直前の話を指す依頼をこなせなかった。Qwen3 の思考モードは結果が同じで約 3.5 倍遅かった。
- **決定:** **判断はプログラムが行い、モデルには狭い役割だけを任せる。** 小さいモデルは嘘・作り話・手本の丸写しをするため。
- **実装:** 1 通のメッセージは「判定（router）→ 検証してタスク操作 → 返事」の順で処理する（`esagent/brain.py`）。
  - 判定役は JSON で `intent`（chat / advise / add / update / complete / delegate）と操作案を返す。
  - 操作案はプログラムが検証してから実行する（AS-04 の安全装置）。
  - **タスク操作後の返事はテンプレート**で、実際に起きたことから作る。モデルには書かせない。
  - 相談（advise）は、**勧めるタスクと理由をプログラムが選び**、モデルは「最初の20分でやること」だけを書く。
  - 待ち時間についての質問はモデルに答えさせず、測った値から作る（#23、AS-16）。
  - 雑談（chat）だけがモデルの自由な文章。ただし「追加しました」「モードを切り替えました」「タイマーを開始しました」など、**実際に起きていない操作を名乗る文はプログラムが打ち消す**。
    打ち消しは**文単位**で行う。名乗った文（追加・登録・作成・更新・完了・変更・分類・移動・設定・削除）を丸ごと消し、`#番号` も消して、「まだ何も登録・変更していないよ」と添える（#11、`brain.drop_false_claims`）。
- **決定:** タスクの相談は**はっきり聞かれたときだけ**行う（「何からやる？」「どうすれば」「優先」「おすすめ」など）。それ以外は会話を続け、話題をタスクにそらさない。
- **決定:** 「〜が欲しい」「〜があればいいな」「〜した方がいい」は、アイデアとして受け止めて返す。E.S. Agent 自体への要望なら「自分の画面は直せない。E.S. Agent のタスクにする？」と聞き、「うん」で 「EsAgent」プロジェクトに登録する。
- **決定（#24、未確認の事実）:** 英語の名前の意味を聞かれたら（「〇〇って何？」）、モデルには**辞書としての訳だけ**を書かせ、「ゲームや作品の中で何を指すのかは調べていないからわからない。/claude で調べられる」とコードで添える（`brain._meaning_flow`）。訳に漢字かひらがなが無い（カタカナの読みや綴りの繰り返し）ときは「うまく訳せなかった」とする。会話・タスク・記憶に出てくる名前と、Es の説明にある名前（Unity など）は通常の会話で答える。
- **決定（#24）:** 「最近何してた？」には、**操作の記録（直近 1 日の ＋ ✎ ✔ → の行）だけ**から答え、それ以外は「メッセージを待っていた。自分から作業はしない」と返す（`brain._activity_flow`）。モデルが面接準備やスクリプト修正を自分の活動のように語っていたため。会話の指示にも「調べていない」「自分の操作は記録にあるものだけ」を足した。
- **決定（#20）:** 「曖昧なら質問してからタスクにしてほしい」のような **Es の振る舞いへの要望**は、タスク操作として扱わない。**モデルを使わず**、「受け答えの決まりはプログラムで決まっていて自分では変えられない。改修のタスクとして登録する？」と返し、タスクは何も変えない（`brain._policy_flow`）。「うん」で EsAgent に登録する。要望の言い方（〜してほしい・〜しないで）と、振る舞いを指す語（質問してから・勝手に・曖昧な・返事は・今後は など）の両方があるときに限る。
- **意図:** 判定役が要望を既存タスクの更新と取り違え、タスク名を要望文に書き換えていた。モデルの返事も「質問してからタスクにします」とできない約束をしていた。
- **決定（#21）:** 「これから自分で直す」のような**ユーザー自身の作業の報告**と、「もう Claude Code に頼んだ」のような**依頼済みの報告**は、依頼として扱わない。**モデルを使わず**、タスクも引き継ぎも作らずに受け止める（`brain._report_flow`）。自分で進める報告で該当タスクがあれば集中タイマーを提案する。「任せたい」「頼む」「準備して」などの依頼の言葉、締切の言葉、「タスクにして」があるときは通常の判定に回す。
- **意図:** 報告から新しいタスクと引き継ぎが作られたり、タスクが完了にされたりしていた。
- **決定:** Es は自分のプログラムや画面を変えられない、Web を見られない、ファイルを読めない。できないことを頼まれたら一文で正直に断り、できることを示す。知識に自信がないときは推測で答えず、`/claude 調べて …` を提案する。
- **実装:** 返事の作成中は進捗を公開する（`/api/progress`）。段階（判断中 → タスクを更新中 → 返事を考え中）、判断内容（例「タスクを追加します ／ 話題: 就活」）、書きかけの返事（ストリーミング）。
- **決定（会話の記憶、#12）:** 会話の履歴は「直近 N 件」ではなく**トークン数の予算**で選ぶ（`history_tokens`、既定 2,000。判定役はその 3/4）。新しい発言から入れ、古いものから落とす。手順スキルにも半分の予算で直近の会話を渡す（`brain.conversation`）。
- **意図:** 直近 4 件に固定していたため、2 往復より前の話を忘れていた。実際のトークン数は判定役 約 1,800・返事役 約 1,100 で、上限 8,192 に対して余裕がある。
- **実装:** 実際に行った操作の記録（＋ ✔ ✎ → の行）は、直前の Es の返事に「（記録: …）」として添えて履歴に入れる。モデルが自分の操作を知るため。
- **決定（#75）:** 会話・記録・タスク・記憶に無いことは「わからない」と答える。以前の発言の具体的な属性を尋ねる想起質問では、対応する宣言本文を取得できなければ、**モデルを使わず**「まだ聞いてない」と答える（`brain._recall_flow`）。助言や直前発言の要約は通常処理へ渡す。
- **実装（記録）:** Ollama への送信内容・返事・`prompt_eval_count`・`eval_count`・`done_reason`・所要時間を `data/llm-requests.jsonl` に 1 行ずつ記録する（5MB で切り替え、`llm_log: false` で停止）。
- **決定:** `num_ctx` は 8,192 のまま（手順スキルはツールの結果で入力が長くなるため）。`keep_alive` は 5 分（他のアプリと VRAM を分け合うため。読み込み時は約 6.2GB）。
- **未解決:** 雑談の返事の質と、相談の「最初の20分でやること」の具体性は、8B モデルの性能の範囲にとどまる。

- **決定（#32）:** タスク判定・最初の20分の提案・手順スキルは、コードの検証で不合格なら理由を渡して最大2回だけ再生成する。タスク判定は操作全体を事前検証し、不合格の間は実行しない。提案は4行以内・冒頭・未完文・元の内容にない会社名や英字／カタカナのツール候補を検証し、通った全文だけ表示する。最後まで不合格なら操作しない／一般的な一歩を案内する。手順スキルは失敗の理由を返し、成功済みの同一呼び出しを再実行しない。雑談には再生成を入れない。
- **決定（#67、実行許可）:** 操作案の形・番号・日付が正しいことと、その発言が実行を許していることは別に確かめる。「実行しないで」「引用」「例文」「〜と同僚が言っていた」「迷っている」「保留」「案として」「変える必要はない」を含む発言、および全部の節が「〜しないで」「変えず」「〜のまま」だけの発言では、**どの書き込み経路でもタスクを変えない**（`esagent/write_guard.py`）。判定役が操作を返しても実行せず「今回はタスクを何も変更していない」と返す。再生成の指示には「操作がなければ actions を [] に」と書き、操作なしを正しい答えとして受け付ける。
- **決定（#67）:** 否定は節ごとに対象と項目を分けて扱う。「資料の修正は完了にしないで、締切だけ明日に」は資料の修正の完了だけを禁じ、締切の変更は行う。「〜のまま」「そのまま」は名前を挙げたタスクのすべての項目を禁じる。項目の名前が無い否定の節（「今のままにして」）は、直前の節で名前を挙げたタスクに掛かる。
- **決定（#76）:** 「〇〇のタイトル・締切・メモ・状態を一覧／表で見せて」のような照会は、**モデルを使わず**名前を挙げたタスク（完了済みも含む）の保存値をそのまま返す（`brain._lookup_flow`）。空の項目は「未設定」と書き、メモを助言の文章に置き換えない。「今の二つのタスク」「それぞれ」は直近の会話で名前の出たタスク、「全部」は未完了のタスク全部。変更の依頼を含む発言は照会として扱わず、何も書き込まない。
- **決定（#70）:** 「実際に何か変えた？」「さっきの操作を説明して」には、**モデルを使わず**操作の記録（＋ ✎ ✔ → ↺ の行）と、対象タスクの今の状態から答える（`brain._action_log_flow`）。今回の質問では何も変えていないことを別に書く。更新の記録は、変えた項目ごとに書く（「タイトル: 旧 → 新」「締切」「メモ追記」「プロジェクト」）。「別の人に頼んだ」の受け止めでは、利用者が言っていない Claude Code などの名前を補わない。
- **決定（#68）:** 作業モードでも、「したい」「教えて」「相談」「まとめて」といった語だけで雑談の判定を作業の助言やタスク一覧の要約に置き換えない。判定役が雑談と答えたら、「何から」「おすすめ」などの次の作業を聞く言葉かタスク名があるときだけ助言にする。「作業の話は一旦やめよう」は雑談として返し、「まず相談したい」「相談を続けたい」は相談の内容で返す。「今の話題をまとめて」は会話の要約として雑談で返す。
- **実装（#32）:** 再試行中は進捗の詳細に「確認して書き直し中」を表示する。モデル要求ログの `validation` に対象と試行番号（0=初回、1/2=再試行）、既存の `elapsed_ms` に各要求の時間を記録する。名称検証は語形による検出であり、すべての固有名詞を識別できる保証はない。

- **実装（#75）:** 最初の一歩の助言・直前発言の理由や要約・操作の説明は未提供属性の想起ガードで遮断しない。合言葉などの想起は対応するユーザーの宣言または明示記憶を取得する。返答モデルには宣言本文だけを渡し、出力が本文と一致しなければ取得済みの原文を表示する。過去の質問や別属性は根拠にせず、取得できない場合はモデルを使わず不明と答える。
- **実装（#75）:** 「さっきの二つの操作を説明して」は想起ガードで遮断せず、#70 の操作記録からの説明（`brain._action_log_flow`）で答える。モデルや Es の過去の返答から操作を推測しない。

## AS-03 会話モード

- **決定:** モードは **作業モード** と **雑談モード** の 2 つ。**明示的にしか切り替わらない。**
- **決定:** 切り替え方 — ヘッダーの切り替えボタン、`/talk`・`/work`、またはモード名をはっきり言う（「雑談モードにして」「作業モードに戻して」）。
- **決定:** 「別の話をしよう」のような言い方ではモードを変えず、その 1 回だけ雑談として返し、「雑談モードにする？」と提案する。
- **決定:** 現在のモードはヘッダーに常に表示する。切り替えるとチャットに「— 雑談モードに切り替えました —」の区切り線を残す。入力欄の案内文もモードで変える。
- **決定:** 雑談モードでは Es からタスクの話を振らない。ただし、ユーザーがはっきり頼んだタスク操作（追加・完了など）は行う。
- **実装:** 同じモードへの切り替えは「もう作業モードだよ」と返し、区切り線を増やさない。

- **実装（#45）:** モード切替の提案には承認・取消を表示し、選ぶまで変更しない。雑談開始後と「話題を選びたい」にはコードで定義した話題を提示する。自由入力を残し、選択しても入力中の文章を消さない。モード名への質問では自動切替しない。
- **実装（#45）:** 同時に有効な提案は1件。提案は応答メッセージと識別子に結び付け、自由入力・別の提案・手動切替・スキル実行で以前の提案を無効化する。古い識別子は現在の提案を消さず変更なしで返し、二重承認は実行しない。「うん」等の短い承認は直前の有効な承認候補だけに適用する。モデルの文章から任意の操作を実行しない。

## AS-04 タスク管理

- **決定:** すべてのプロジェクトのタスクを **1 つのリスト**で横断管理する。
- **実装:** タスクの項目 — タイトル、プロジェクト、状態（todo / doing / delegated / done）、締切、メモ、繰り返し規則（AS-05）（`esagent/db.py`）。
- **実装:** プロジェクト — `GameProject` 配下の Unity プロジェクト（`Assets` と `ProjectSettings` があるフォルダ）を起動時に自動登録する。「就活」「全般」は設定で追加する。Google のリスト（AS-10）も、プロジェクトとして取り込む。
- **決定:** メッセージ中で名前を挙げたプロジェクトが無ければ自動で作る（例:「EsAgentカテゴリーで登録して」）。
- **決定（#22）:** `/add` の `#プロジェクト` は自動で作らない。見つからなければ登録を止めて書式と候補を示す（AS-07）。
- **決定（#7、プロジェクトの文脈）:** プロジェクトに**説明**と**関連フォルダ**を持たせる。説明は、相談の「最初の20分」・`/morning` などの手順スキル・判定役のプロジェクト一覧（先頭 60 文字）に渡す（`esagent/projects.py`）。「就活」「Sinfonia Studio」のような大きなくくりの中身をモデルに伝えるため。
- **実装:** 管理画面の「プロジェクト」タブで編集する。「説明を自動で作る」は、関連フォルダとその直下のフォルダの README / AGENTS.md / CLAUDE.md の冒頭を読み、モデルが 1〜3 文の下書きを作る。保存するまで反映しない。関連フォルダは実在するものだけ受け付け、Claude Code への引き継ぎの作業フォルダにもなる（AS-09）。
- **決定（モデル対策の安全装置）:**
  - 追加は、発言に新しい用事らしい言葉（まで・締切・提出・面接・予定・追加・登録など）があるときだけ受け付ける。
  - 発言から読み取れないタスク名は追加しない。ただし「タスクにして」「登録して」とはっきり頼まれたときは、モデルの言い換えを許す。「上記の」「それぞれ」のときは、直前のユーザー発言も照合に使う。
  - 過去の日付の締切は設定しない。
  - 「〇〇社」がタスク名から抜けていたら補う。
  - ほぼ同じ名前の未完了タスクがあれば、二重に登録しない。
  - 存在しない番号や、手本の番号を真似した操作は、発言内容とタスク名の一致で対象を特定し直し、特定できなければ実行しない。
  - 引き継ぎ準備済みのタスクをもう一度任されたら、重複して作らず「準備してある」と返す（失敗の案内にしない、#21）。何も変えなかった更新は「どう変えるか読み取れなかった」と返す。
  - **更新は、変える項目ごとに発言の裏付けを求める（#20）。** 名前の変更は「名前」「タイトル」「『〜』に変えて」、締切は日付や「締切・延期・それぞれ」など、メモは「メモ・詳細・追記」などかタスク名への言及、プロジェクトの移動はプロジェクト名が発言にあるときだけ反映する。どれも無ければ「変えていません」と記録して何もしない（`brain._intended_update`）。番号が実在するだけでは更新しない。
  - 「それぞれ〜」の一括更新で、発言の語（例「ノート」）が一部のタスク名にしか含まれないときは、そのタスクだけに絞る。
  - **対象は利用者の言葉が指すタスクだけ（#72）。** 番号が実在するだけでは対象にしない。発言の `#番号`・タスク名の全文（「資料の修正案」があれば短い「資料の修正」より優先）・プロジェクト名（同名のタスクが複数あるとき）・はっきりした名前の一致のいずれかが要る。「」で挙げた名前がどのタスクにも当たらないときは、**モデルを使わず**「見つからなかった」と返して何も変えない。同名のタスクがあってプロジェクトが無ければ実行せず確認する。「それ」「その」は直近の会話（操作の記録を含む 4 件）で一意に決まるときだけ使い、複数のタスクを指しうるときは「どれのことか」を聞く（「それぞれ」「両方」は除く）。
  - **締切は発言から日付が決まるときだけ設定する（#74）。** 注釈済みの日付（明日(=…) など）があればその日だけ、「1週間ずつ」「来週」「3日後」のような量・期間があればモデルの計算を受け付ける。「いつか」「余裕のある日」「そのうち」のような言葉だけなら、**モデルを使わず**日付を聞き返す。「2月30日」のように日付にできない指定は、日付が理由だと返して既存の締切を保つ。
  - **メモは利用者の内容があるときだけ追記する（#67、#73）。** 「完了」「未完了」「変更しないで保留中」のような操作の言い換えだけのメモは追記しない。メモの言葉が無い場合は、タスク名への言及に加えてメモの内容が発言と一致することを求める。
- **決定（#73）:** 「〇〇を未完了に戻して」「完了を取り消して」は、**モデルを使わず**名前で完了済みも含めて対象を特定し、状態を todo に戻す（記録は「↺ #番号 タスク名 を未完了に戻しました」）。すでに未完了なら変えずにそう返し、対象が無い・複数なら確認する。別の項目の変更が混ざっていても状態だけを戻し、残りは未処理だと伝える。
- **決定（#69）:** 「〇〇は一旦忘れて」で、そのタスクを**翌日まで提案から外す**。対象未指定の場合だけ直前の推薦を避ける。明示対象・比較の優先対象・同じ作業の続きはローテーションより優先する。曖昧な対象は確認し、明示除外は後続候補とモデル生成の手順にも適用する。
- **決定:** 繰り返しタスク（ゲームのウィークリーなど）は、リセットの前日になるまで提案の順位を下げる。
- **実装:** タスク名をクリックするとメモ欄が開き、編集して保存できる。`/note` でも追記できる。

- **決定（#54）:** タスクの重複防止は「登録済みで新規追加なし」と返し、反映失敗として扱わない。追加依頼に既存と異なる締切・プロジェクト・メモ・繰り返しが含まれる場合は未反映の条件を記録して、既存タスクの変更内容を確認する。重複を防いだだけで新しい条件まで保存したと断言しない。新規操作・登録済み・未反映の結果が混在した場合もそれぞれ案内する。

- **実装（#50）:** Esの改善要望は、直後の明示的な参照（「その機能は…」等）や同じ分野を指定した続きの発言を下書きへ集める。要望の本文を保持し、背景・目的・条件・未決事項を推測で補わない。条件追加時には登録前の内容を表示し、現在の承認ボタン／「それをタスクに登録して」で保存する。保存した詳細を返答に表示して、タスクのメモ欄で確認・訂正できる。無関係な話題・手動モード切替・スキル・取消は下書きを終了し、古い提案で新しい条件を登録しない。64発言を超える下書きは内容の再指定を求める。
- **実装（#50）:** 「タスク名」の詳細に追記して：内容 は既存メモと他の項目を保持し、既存内容と重なる文を増やさない。「詳細を訂正して：旧文 → 新文」は旧文が1か所の場合だけ変更する。対象名／番号が不在・複数なら保存せず確認する。「詳細にこれまでの会話を追記して」は直近80件のユーザー発言から、対象を明示した発言と直後の関連する続きを保存する。Esの発言や話題変更後の不明な参照は含めず、明示した訂正は再追記にも適用する。保存時に元の詳細が変わっていた場合は上書きせず再確認を求める。詳細と訂正情報は同じトランザクションで保存する。過去の未修正タスクを一括変更しない。

- **実装（#71）:** 詳細の前処理は専用書式と明示的な会話追記だけを扱う。自然文の複合更新・詳細保持・照会は通常判定へ渡す。タスク名の引用と追記本文を分離し、実行禁止・引用・例文は保存しない。

## AS-05 繰り返しタスク

- **決定:** 決まった時刻にリセットされるタスクを扱う（例: Warframe のウィークリー「深淵アルキメディア」「次元アルキメディア」「Night Wave」は**毎週月曜 9:00 リセット**）。
- **実装:** 規則は `weekly <曜日0-6> HH:MM` か `daily HH:MM`。リセット時刻を過ぎると状態を未完了に戻し、締切を次のリセット日にする（`esagent/recurring.py`）。
- **実装:** 指定方法 — 発言に「毎週月曜9時」「毎日5時」を含める、または `/repeat 番号 毎週月曜9時`（`なし` で解除）。タスクには 🔁 を表示する。
- **決定（#6）:** 繰り返しは **E.S. Agent がリセットする方式で確定**。Google ToDo 側の繰り返し設定は使わない。Google Tasks の API には繰り返しの項目が無く、設定も読み取りもできないため。リセット（未完了に戻る・締切が次の回になる）は通常の変更として Google とカレンダーに同期され、スマホでも次の回のタスクとして見える。Google ToDo アプリで繰り返しを設定しても E.S. Agent には伝わらない。
- **意図:** カレンダーに繰り返し予定を作る案は、ToDo のチェックと連動せず二重管理になるので採らない。
- **実装:** 「繰り返しって Google で設定されてる？」のような繰り返しの仕組みへの質問には、**モデルを使わず**この仕組み・API の制約・いま繰り返しになっているタスク・設定方法を答える（`recurring.explain`、`brain._repeat_question_flow`）。`/repeat` の返事にも「Google ToDo 側の繰り返し設定にはならない」と添え、Google に繰り返しを設定できたとは言わない。

- **決定（#53）:** 会話の明示的な繰り返し依頼はモデルのメモ生成に任せず、対象・周期をコードで特定して実際の `repeat` と次回締切を設定する。「参照元と同じ周期で新しい名前を追加」「対象を参照元と同じ周期に設定」「対象を毎週／毎日の時刻に設定」に対応し、返答は保存された周期・締切から作る。同じ周期での追加は参照元のプロジェクトを引き継ぐ。参照元の不在・複数・周期なし、不正な時刻、対象不明は変更せず確認する。直後の「それ」は直近の実操作記録で対象が一意のときだけ参照し、別の話題を挟んだ場合は対象を確認する。既存タスクのメモ・名称・完了状態は変更せず、解除時は締切を維持する。期日だけの依頼を周期へ変換しない。

## AS-06 日付の解釈

- **決定:** 相対的な日付は、モデルではなくプログラムが日付に直してから渡す。
- **意図:** 小さいモデルは「金曜」を木曜の日付にするなど、曜日の計算を間違えるため。
- **実装:** 対象 — 今日・明日・明後日、〇曜（今週・来週・再来週）、〇月〇日・〇/〇、〇日後。例「金曜」→「金曜(=2026-10-09)」（`brain.annotate_dates`）。曜日だけなら今日以降で最も近い日。60 日以上前の月日は翌年として扱う。

## AS-07 スキル（`/` の呼び出し）

- **決定:** `/` は Claude のスキルと同じく、**ファイルで定義した決まった動きの呼び出し**とする。
- **実装:** 1 スキル = `skills/<名前>/SKILL.md`。先頭（frontmatter）に `name` / `description` / `argument-hint`、必要なら `action`（固定動作）と `save-args: memory`（入力を先に記憶へ保存）を書く。本文は手順。**ファイルを編集すれば即反映、フォルダを足せば `/名前` が増える**（`esagent/skills.py`）。
- **実装:** 2 種類ある。
  - **すぐ動くスキル**（`action:` あり）— モデルを使わず、約 0.1 秒で確実に動く（`esagent/actions.py`）。help / tasks / next / summary / add / done / due / note / repeat / claude / talk / work / remember / memory / forget / sync / clear / model。
  - **`/add`（#22）:** `/add タイトル [日付] [#プロジェクト]`。`#` の付いた語がプロジェクト。**存在しないプロジェクトを指定したら何も登録せず**、正しい書式・候補（「もしかして: /add …」）・プロジェクト一覧を返す。プロジェクトなしは `#` を書かないか `#未分類`。使い方には完成した入力例を添える。
  - **Es が手順どおりに動くスキル** — Qwen3 が本文の手順に沿い、ツール（タスクの一覧・追加・更新・完了・引き継ぎ・記憶・集中の提案）を使って進める。`/morning`（今日の 3 つ）、`/plan 目標 [期限]`（3〜6 個に分けて締切つきで登録）、`/review [感想]`（振り返り）。
- **実装（モデル対策）:** 同じツール呼び出しの繰り返しは実行せずに知らせる。手順の上限（8 回）に達したら、そこまでの結果で返事をまとめる。返事に含まれるタスク番号や `[プロジェクト名]` は消す。ツールの結果には実際に登録した締切を返す。
- **実装:** 入力欄で `/` を打つと候補を表示し、↑↓ で選んで Tab で補完する。
- **決定:** 手順の最後に「集中タイマー始めよっか？」と提案した場合、次の「うん」で**本当に**タイマーを開始する。

- **実装（#45）:** 集中開始・Esの改善タスク登録の提案にも承認と取消を表示する。開始時に対象の存在・未完了・名称を再確認する。改善タスクは提案時の要望本文をメモに保存し、承認ではモデルを呼ばず1度だけ登録する。

## AS-08 記憶

- **実装（#46）:** 記憶についての質問・引用・否定・過去の依頼への言及・改善要望では保存しない。自然言語の保存依頼は「内容。覚えておいて」「覚えておいて：内容」の明確な形式で、その本文だけを保存する。モデルの要約や過去の返事から内容を推測しない。「それ」等の対象不明な依頼は内容を確認し、`/remember 内容` を案内する。保存したとの名乗りは実際の保存時だけ返す。
- **決定:** 「覚えておいて」や `/remember` で、ユーザーについての一文を保存する。直前の Es の発言を指していれば、その要点を保存する。
- **実装:** 記憶は会話の返事を作るときに毎回参照する。`/memory` で一覧、`/forget 番号` で削除。`/review` は感想を自動で保存する（`save-args: memory`）。

## AS-09 Claude Code への引き継ぎ

- **決定:** コードの修正・調査・長い文書など、Es には重い作業は Claude Code に任せる。引き継いだ作業は、**このデスクトップアプリのセッションとして開き、ユーザーがそのまま会話を引き継げる**ようにする。
- **実装:** `claude://code/new?folder=<作業フォルダ>&q=<依頼文>` を開く。依頼文は入力欄に入るだけで、**送信はユーザーが行う**（`esagent/handoff.py`）。作業フォルダは、Unity プロジェクトのタスクならそのプロジェクトのフォルダ、それ以外は `workspace/`。
- **実装:** 依頼文 — タスク名・プロジェクト・締切・メモ・直近の会話・完了報告の依頼。全文を `data/handoffs/handoff-<番号>.md` に保存する。リンクが長すぎるとき（エンコード後 28,000 文字超）は会話を省き、全文ファイルの場所を書く。
- **制約:** URL はコマンドライン引数として渡り、上限が約 32,767 文字。日本語 1 文字はエンコードで 9 文字になる。
- **実装:** Claude Code には MCP サーバー `esagent` を登録してある（`esagent/mcp_server.py`）。ツール: list_tasks / get_task / add_task / update_task / complete_handoff。Claude Code は作業後に `complete_handoff` で結果をタスクのメモへ書き戻す。
- **決定（#21）:** 引き継ぐのは、ユーザーが任せたいと言ったときだけ。「自分で直す」「もう頼んだ」という報告では引き継ぎを作らない（AS-02）。同じタスクの引き継ぎは 1 つだけで、重ねて頼まれたら「準備してある」と返す。

## AS-10 Google ToDo リストとの同期

- **実装（#33）:** 未送信のタスク変更は `rev` と `synced_rev` の差で検出する。同期と同じ秒の編集・繰り返しリセットも次の同期対象になる。送信中に追加の編集があれば、送った版だけを同期済みにし、後の編集を残す。既存データは従来の時刻比較で同期済み/未送信を引き継ぐ。競合比較用のローカル編集時刻はマイクロ秒精度で保存する。
- **決定:** タスクは Google ToDo リストと双方向に同期する。**オンラインのときに同期し**、オフライン中の変更は回線が戻ったら送る。
- **実装:** Google のリスト = E.S. Agent のプロジェクト。既定のリスト「マイタスク」= 未分類。プロジェクトにタスクができたとき、同名のリストを作る（`esagent/gsync.py`）。
- **実装:** 同期の間隔 — 3 分ごと、E.S. Agent で変更したら即時、オフラインなら 30 秒ごとに再試行、エラーなら 5 分後。両側で変わっていたら後から変更した方を優先する。Google 側で削除されたタスクは E.S. Agent からも削除する。
- **実装:** 認証は OAuth（ループバック＋PKCE、`esagent/gauth.py`）。接続情報は `secrets/google_token.json`。
- **制約:** OAuth アプリが「テスト中」の間は、更新トークンの期限が **7 日**。切れたら画面に「再接続」が出る（タスクのデータは消えない）。
- **未解決:** OAuth アプリの本番公開。2026-10-07 時点では「アプリを公開」ボタンが押せなかった。

## AS-11 Google カレンダー

- **決定:** 締切を Google カレンダーにも入れる。
- **実装:** E.S. Agent 専用のカレンダー「EsAgent 締切」を作り、締切つきの未完了タスクを**終日の予定**として入れる。通知は**前日 9:00**（予定の開始 0:00 の 900 分前）（`esagent/gcal.py`）。
- **実装:** 予定には E.S. Agent のタスク番号を記録し、毎回タスク一覧と突き合わせる。締切の変更・名前の変更は予定に反映し、完了や締切なしになったら予定を消す。ユーザーが自分で追加した予定には触れない。カレンダーごと削除されたら作り直す。
- **決定:** 権限は最小限にする（`calendar.app.created` = E.S. Agent が作ったカレンダーだけ操作できる）。ほかのカレンダーは読み書きしない。
- **実装:** 同期は E.S. Agent → カレンダーの一方向。カレンダー側で予定を動かしても、タスクの締切には戻らない。

## AS-12 コンパニオン（デスクトップの黒猫）

- **決定・実装（#35）:** チャットの専用ウィンドウが開いて最小化されていない間、デスクトップの猫と吹き出しを自動で隠す。別アプリに覆われても隠したまま。閉じる/最小化で、有効設定の場合のみ戻す。500msごとにウィンドウ状態を調べ、起動時から開いている場合も適用する。設定値は書き換えない。非表示中の吹き出しは後から再生しない。手動無効時は従来どおりプロセスを終了し、無効状態で自動起動しない。
- **決定:** Es は**黒猫**。**デスクトップに常駐し、常に最前面**に出る（大きさは約 80px の指定に対し、実寸は約 75px）。
- **決定（#3）:** チャット画面のバーにも、なかよし度の隣に**小さな黒猫と吹き出し**を置く（猫と一言が入る最低限の広さ）。動きはデスクトップの猫と同じ。その下の「デスクトップに表示」でデスクトップの猫を出し入れでき、設定は保存される（`pet_enabled`）。デスクトップの猫の右クリック「デスクトップから消す」も同じ設定を切り替える。
- **実装:** バーの猫は暗い画面でも見えるよう、明るい下地の上に描く。
- **実装:** 素材は Pet Cats Pack（LuizMelo、**CC0**）の Cat-2（黒猫）。50×50 のドット絵を 3 倍で表示する（`esagent/pet.py`、`esagent/static/cat/`）。猫の種類（`pet_cat`、6 種）と倍率（`pet_scale`）は管理画面から変えられ、デスクトップの猫は右下の位置を保ったまま、再起動なしで切り替わる（#2）。
- **実装:** 背景が透明で、タスクバーに出ない小さな窓。初期位置は画面右下のタスクバーの上。ドラッグで移動でき、位置を記憶する。二重には起動しない。
- **決定（操作）:**
  - **シングルクリック** — 「にゃ？」と反応するだけ。
  - **ダブルクリック** — チャット画面が開いていれば前面に出す。無ければ開く。
  - **マウスを乗せる** — 集中中・休憩中なら残り時間とタスク名を出す。
  - **右クリック** — 集中の開始・一時停止・リセット、チャットを開く、BGM の再生・停止、30 分隠れる、デスクトップから消す。
- **実装（状態と動き）:** 通常 = 待機（ときどき毛づくろい・かゆがる・おすわり）／集中中 = **丸まって眠る**（z）／集中の終了 = のび → 休憩中は寝そべる／考え中 = おすわり（…）／タスク完了・話しかけ = 鳴く（♪）／締切切れ = かゆがる（!?、1 日 1 回）／サーバーかモデルが止まっている = 丸まって眠る（💤）。
- **実装:** 吹き出しで知らせる。集中が終わると「『〇〇』、終わった？［終わった］［まだ］」、休憩が終わると「次、いく？［集中する］」。
- **確認済み（#10）:** ダブルクリックでのウィンドウの前面化はユーザーが実機で確認した。

## AS-13 集中タイマーとなかよし度

## AS-14 BGM と環境音

- **決定:** BGM は YouTube と連携し、再生先はリンクの種類から自動で選ぶ（#65）。YouTube／YouTube Music／埋め込みのモード選択は表示しない。
  - **YouTube の検索・ライブラリ（#37）** — BGM 欄の「動画・プレイリスト」から動画検索、自分のプレイリスト、プレイリスト内の動画を表示する。一覧は20件ごとのページ送り。一覧を開くとアプリ内の再生を一時停止し、動画を選ぶと一覧を閉じてアプリ内の公式プレーヤーで再生する。
  - **Google 接続（#37）** — 「GoogleでYouTubeに接続」を押した場合だけ `youtube.readonly` を追加で要求する。既存の ToDo・カレンダーと同じ OAuth クライアントを使い、通常のブラウザで同意を受ける。必要な権限が一部拒否された場合や更新トークンが無い場合は、以前の接続を保持する。YouTube Data API v3 の有効化が必要。
  - **通常の再生（#63）** — チャット画面の右上に埋め込んだプレーヤー。通常のYouTube動画・短縮URL・プレイリスト・動画一覧の選択はここで再生する。Musicのリンクは公式Musicサイト、チャンネルの現在のライブを指すリンクは公式YouTubeへ自動で切り替える（#65）。プリセットも同じ判定を使う。画面再読み込みでは保存URLから表示先だけを復元し、外部ウィンドウは起動しない。YouTube以外のURLは受け付けない。
  - **再生できないとき（#63）** — 再生エラー時に「YouTubeで開く」を提示し、選んだ場合だけ別ウィンドウを開く。「アプリ内再生に戻る」や通常動画の選択は外部再生を一時停止してアプリ内へ戻す。Musicの動画・プレイリストから戻る場合は同じIDを通常YouTubeで再生する。Musicのホームやライブラリのように動画を特定できないリンクでは戻るボタンを無効にする。別の外部リンクを選んだときも先に外部再生を一時停止する（#65）。外部での代替再生も集中連動を維持する。

- **決定:** 「集中中だけ流す」をオンにすると、集中の開始で再生し、休憩・一時停止・リセットで止める。**自分で選んだ BGM だけ**を流す（プリセットを勝手に流さない）。
- **制約:** YouTube の API 規約により、埋め込みプレーヤーは見える状態で再生する（隠して再生しない。BGM 欄を折りたたむと一時停止する）。埋め込みを禁止している動画（Lofi Girl のライブなど）はこのモードでは流せない。Premium のバックグラウンド再生は公式アプリとサイトだけの特典で、埋め込みには効かない。
- **制約（#37）:** OAuth は一覧の読み取り権限であり、埋め込みプレーヤーのログイン・Premium 機能を保証しない。年齢制限・非公開・埋め込み禁止動画は再生できない場合がある。通信失敗・権限不足・API未有効化・利用上限は欄内に案内し、再生できない場合は公式サイトで開ける。検索は入力を送信した場合だけ実行する。
- **実装:** ウィンドウ（動画・音楽）の再生・停止は、Windows のメディア操作（GSMTC）で行う。**YouTube のウィンドウだけ**を操作し、ほかのアプリや Edge のほかのタブには触れない（`esagent/media.py`、`media.ps1`）。PowerShell は同時に 1 つだけ動かす。
- **実装:** 一度再生できた URL は、タイトルつきでプリセットに残す（`config.json` の `bgm`）。
- **実装:** 環境音は雨と風。音声ファイルを使わず、ブラウザ内で作る。
- **確認済み（#10）:** YouTube ウィンドウの集中連動はユーザーが実機で確認した。

## AS-16 返事待ちと再送

- **実装（#39）:** 通常チャットだけでなく固定/手順スキル・存在しないスキルでも受信・開始・完了時刻を記録する。保留後は最初の送信/受信時刻を維持し、開始時刻はロック獲得後に記録する。画面はミリ秒とUTCオフセットを含むISO時刻を送信し、サーバーはDBのローカル時刻へ正規化する。時刻を送らない旧画面やAPI要求の送信時刻は補完しない。
- **実装（#40）:** 画面の通常送信・順番待ち・再接続再送では同じ要求IDを保持し、再読み込み前に送信待ちへ保存する。サーバーは要求ID・本文のハッシュ・HTTP応答をローカルDBへ保存し、同じ送信への再要求には保存した結果を返す（スキル・返事待ちも対象）。同時再送も処理は一度だけ。同じIDの異なる本文は拒否する。処理の途中でサーバーが停止し結果が不明なら、自動で再実行せず履歴とタスクの確認を案内する。旧画面などIDなしの送信は互換対応するが重複防止の対象外。画面の保存機能が利用可能であることが再読み込み後の復元の前提。
- **実装（#40）:** 返答送信時の接続中断は処理失敗と分けてINFOで記録し、切断済みの接続へ500を送り直さない。応答の途中切断は画面で再接続再送の対象にする。処理本体でエラーになった要求もその結果を保存し、操作が途中まで行われている可能性を考慮して同じ要求を再実行しない。

- **決定:** メッセージを取り消さない。**残しておき、あとで返事をする**（Claude と同じ考え方）。
- **実装:** モデルの準備ができていないとき、メッセージに「⏳ 返事待ち」を付けて残す。サーバーが 5 秒ごとに確認し、準備ができたら**古い順に返事**する。スキルも同じ。遅れた返事は「（さっきの『〇〇』への返事）」で始める。
- **実装:** サーバーにつながらないとき、メッセージは「再接続を待っています」として送信待ちに残り、3 秒ごとに送り直す。送信待ちは保存しているので、画面を再読み込みしても消えない。
- **決定（#23）:** 「考えるの長くない？」「まだ？」「何が起きてたの？」のような**待ち時間についての質問**は、**モデルもロックも使わず、すぐ**、測った値だけで答える（`brain.status_lines`）。いま作っている返事（段階・経過時間）、返事を保留しているメッセージの件数、直前のメッセージの「送信 → 受信 → 開始 → 完了」の内訳（モデルの準備待ち／画面での順番待ち／前の処理の待ち／返事の作成）、モデルにつながっているか。遅れを否定せず、1 分以上なら謝る。測れていない原因は「わからない」と言い、理由を作らない。
- **実装:** ユーザーのメッセージに、送信ボタンを押した時刻（画面から `queuedAt`）・サーバーが受けた時刻・処理の開始・完了・待った理由（`wait_reason`）を記録する。画面は、返事を待っている間でも、この種の質問だけは送信待ちに並べずにすぐ送る（パターンは `GET /api/chat/bypass`）。

## AS-17 安全とプライバシー

- **実装（#36）:** ローカルCLI `esagent/diagnose.py` で、会話DBの完了件数・送信から完了までの中央値/p95/最大・遅延上位の時刻と待ち時間、モデル要求の時間分布と失敗件数、サーバーの警告/エラー件数と時刻を診断する。期間・上位件数・テキスト/JSONを選択でき、明示した場合だけ新規ファイルへ保存する（入力フォルダへの保存・既存ファイルの上書きは拒否）。DBは読み取り専用、モデルログの `.1` とサーバーログの既存ローテーションも対象。欠損・旧列・破損行・測定不能を報告する。会話本文・モデルの入出力・秘密情報・設定値・絶対パスは出さず、外部送信やアプリ初期化も行わない。共通IDがない会話とモデル要求の相関は不明とし、時刻だけで原因を断定しない。ログ停止設定は変更しない。指標の限界・利用方法は `docs/log-diagnostics.md`。
- **実装:** サーバーは `127.0.0.1` だけで待ち受ける。Host ヘッダーが 127.0.0.1 / localhost 以外の要求は拒否する（DNS リバインディング対策）。書き込み系の API は独自ヘッダー `X-E.S. Agent: 1` を必須にする（ほかのサイトから操作されないように）。
- **実装:** Google の OAuth の一時コードと state は、ログに伏せ字で記録する。
- **実装:** 静的ファイルは `static/` の中だけを返す（`..` などでフォルダの外に出られない）。
- **実装:** 管理画面は、実在するテーブル名だけを受け付ける。`settings` のうち名前にトークン・シークレットなどを含む値は伏せる。`secrets/` の中身は表示しない。
- **決定:** カレンダーへの書き込み、規約への同意、アカウント操作など、取り消しにくい操作はユーザーが確認してから行う。
